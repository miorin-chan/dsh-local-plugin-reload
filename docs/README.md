# 项目文档

- [产品设计](../DESIGN.md)：用户问题、操作流程、安全边界与成功标准。

`plugins.tab` 提供本地插件卡片，卡片用 `openPackage` 打开原生详情页。
卡片沿用「已安装」中用户插件的顺序，按去掉 npm 作用域和 DSH 前缀后的包名排序，显示标题仍随界面语言变化。
`plugins.detail.badge` 在标题旁放置「本地」徽章。来源编辑和重载只在调试时使用，
因此注册到 `plugins.detail.section`，排在原生「来源信息」之后，默认折叠为一行「本地重载」标题。
可重载时徽章本身也是按钮，点击后展开该节、滚动到可见处并聚焦折叠按钮；不可重载的页面只显示普通徽章。
Atlas 管理的临时安装目录显示只读「本地安装」说明，来源变更交给 Atlas 本地开发插件（`@miorin/dsh-atlas-dev`），
不经过通用重载；启用该插件后本扩展自动让渡其余包的详情徽章。
重装经过现有插件管理权限检查，进度弹窗放在 `shell.overlay` 中，因此目标插件从面板移除时，弹窗仍能显示结果。
来源和启用状态以 Host 返回的已安装清单为准，启停和卸载交给官方插件管理服务。
可卸载的插件停用后，卡片上才会显示垃圾桶。
确认后重新核对目标仍处于停用状态，再调用 `pluginManager/removeBundle` 并刷新清单，不切换页签。
构建时直接打包同版本官方 `Switch`、`Tag`、`Button`、`Input`、默认插件图标、`IconTrashOutlineRegular` 及相应样式。
当前 `plugins.tab` 由扩展渲染卡片内容，官方卡片组件和卡片启停控制器没有通过该接口公开。

新检出后在项目根运行 `npm ci`，安装依赖并构建插件。
改动源码后用 `npm run build` 更新产物，再运行 `npm run check`。
界面验证时，打开一个本地链接的插件和一个官方插件的详情，检查徽章和重载入口。
使用一次性 profile 确认卡片卸载后仍停留在「本地」，同时检查重装、启用状态恢复，以及扩展停用后入口消失。

开发约定见 [AGENTS.md](../AGENTS.md) 与 [AGENTS.local.md](../AGENTS.local.md)。
